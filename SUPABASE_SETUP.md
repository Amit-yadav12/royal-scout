# Supabase setup

Use one Supabase project for Vercel and Render. Configure the project URL, a publishable key for browser sign-in, and a private `sb_secret_*` server API key in server-only Vercel and Render variables. The backend authentication helper sends a new secret key as `apikey` only. Legacy `SUPABASE_SERVICE_ROLE_KEY` JWT deployments remain supported with both `apikey` and `Authorization: Bearer`. Never put either server credential in browser code or logs.

Create private Storage buckets `uploads`, `royal-scout-artifacts`, and `fixtures`; migration `0006_private_storage_buckets.sql` does this. Keep them private. Apply migrations `0001` through `0009` and `20261116171951_lock_profile_role_updates` using the Supabase migration workflow. `0007` restricts queue SECURITY DEFINER RPC execution to the `service_role`; the new role-lock migration prevents authenticated users from editing their own staff role. Production users authenticate via Supabase Auth; signed-upload issuance is server-side and object paths are scoped to project/dataset IDs. Only profiles assigned `analyst`, `scout`, or `admin` may issue upload signatures, queue jobs, or retry jobs. Worker source access accepts only configured upload bucket or fixtures; outputs are written to the artifact bucket.

In Supabase Auth → URL Configuration, set the production Site URL and allow the exact app callback (for example `https://your-domain.example/auth/callback`) plus your local development callback. Password recovery and email-link sign-in exchange the PKCE code at this server route; do not allow wildcard external redirect domains. Keep Supabase Auth `disable_signup=true` and provision staff explicitly through the trusted Supabase/admin workflow; new accounts default to `viewer`, email-link requests cannot create users, and users cannot change their own role.

Do not grant anonymous access to queue rows or private objects. The service key is only for trusted server-side operations. Dashboard authenticated-user requests use the user's Supabase session, not the server API key. `/health/ready` checks table and bucket reachability without returning credentials.
